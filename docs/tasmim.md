# التصميم والمنهجية — بَيِّن

## الفكرة العلمية

المقياس المستخدم هو **سؤال المقدمة الخاطئة** (False-Premise Question) — مفهوم منشور في أدبيات تقييم النماذج اللغوية: سؤال صياغته سليمة لكنه مبني على معلومة خاطئة. المجيب الجيد **يرد السؤال** لا يجيب عليه.

## لماذا نخلط أسئلة سليمة؟

من يشكّ في كل شيء ليس متبيِّناً — بل مرتاباً. لذلك يحوي البنك أسئلة سليمة **ضابطة**: النجاح فيها هو الإجابة العادية. الفضيلة في **التمييز** لا في الرفض المطلق.

## قواعد تحمي القياس

1. **المعيار يُجمَّد قبل قراءة النتائج** — لا يُعدَّل الحكم بعد رؤية الإجابات.
2. **السؤال يُحرق بعد كشفه** — لا يُعاد نفس السؤال على نفس المجيب.
3. **الحدود تُعلَن ولا تُخفى** — انظر أدناه.

## الحدود المعلنة (بصدق)

- الحكم الآلي **لفظي بسيط**: يبحث عن ألفاظ التصحيح في الإجابة. قد يخطئ في الحالتين (إجابة صحيحة بألفاظ غير متوقعة، أو ألفاظ تصحيح في سياق خاطئ). الحكم النهائي بمراجعة بشرية.
- البنك التجريبي **صغير (5 أسئلة)** — النتائج مؤشر لا برهان، ولا تُعمَّم.
- اختبار البشر يتطلب **موافقة مسبقة** وبروتوكولاً أخلاقياً (ركن تخصص علم النفس في الفريق).

## المعمارية

```
bayyin.py          ← السكربت الرئيسي (Python قياسي، صفر مكتبات خارجية)
bank/asila.json    ← بنك الأسئلة (نوعان: batil / salim مع مفتاح الحكم)
natijah/*.json     ← نتائج كل تشغيل (النموذج، الوقت، الإجابات، الحكم)
index.html         ← صفحة النتائج (عربية RTL، تعمل على GitHub Pages)
```

الاتصال بالنماذج عبر Ollama API المحلي (`localhost:11434`) — **لا يغادر أي نص الجهاز**.
